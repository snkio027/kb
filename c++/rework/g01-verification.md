# G1 新稿的实验与验证边界

本记录对应[存储、对象与生命周期](g01-storage-and-lifetime.md)与[借用、范围与访问失效](g01-borrowing-and-invalidation.md)。正文负责解释模型，本记录负责说明实际执行了什么；G1 新稿仍待读者精读，不使用工具结果替代编辑接受。

## 输入与执行方式

[执行脚本](verify_g1.py)从两篇新稿中提取全部九个 C++ 文件：一个共享头文件、六个正常运行程序、一个编译负例、一个仅限 ASan 的未定义行为反例。每个编译器使用独立临时目录，每次运行都是新进程，静态计数器不会跨实验继承状态。程序自身检查数值、对象计数及容器关系，执行器同时检查退出状态和完整输出，不只检查能否编译。

进程启动、超时和取消处理复用已有 `c++/learning/verify_g.py` 的辅助函数，没有修改该执行器，也没有启动其旧实验。新脚本记录这项依赖的 SHA-256。编译失败必须匹配只读访问诊断；ASan 反例必须先编译成功，再同时满足指定退出码和目标诊断。超时、任意崩溃与缺少工具不算通过，sanitizer 环境不可用时明确记为 SKIP。

[原始结果](g01-results.json)保存正文、脚本、辅助文件与九份提取源码的摘要，以及完整命令、标准输出和诊断。它不包含出版检查，也不更新旧实验 JSON。

## 本机环境

| 环境 | 实际身份 |
| --- | --- |
| 平台 | macOS 26.7，arm64 |
| 编译器 A | Apple Clang 21.0.0，`clang-2100.3.34.2`；`_LIBCPP_VERSION=220106` |
| 编译器 B | Homebrew Clang 23.1.2；`_LIBCPP_VERSION=230102` |
| 语言模式 | `-std=c++23`，两者的 `__cplusplus=202302L` |
| 普通运行 | 分别使用 `-O0 -g` 与 `-O2`，均开启 `-Wall -Wextra -Wpedantic` |
| 正例动态检查 | `-O1 -g -fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer` |
| 受控反例 | `-O0 -g -fsanitize=address -fno-omit-frame-pointer`；仅此进程执行失效访问 |

两套编译器均使用 libc++，不能视为验证了两类标准库或两个操作系统。固定设置 `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1:abort_on_error=0:exitcode=86:symbolize=0`，关闭外部符号化与泄漏检测；`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=0`。不按地址、栈行号或时序差异判定结果。

## 分开报告的结果

| 证据类型 | 本轮结果 | 可以支持的结论 |
| --- | --- | --- |
| 正常编译与运行 | 六个程序 × 两种优化设置 × 两套编译器，共 24 项 PASS | 实际源码的退出状态和完整输出符合各自预期 |
| 编译负例 | 一个程序 × 两套编译器，共 2 项 PASS | 编译器拒绝通过 `const Reading*` 修改成员，并给出目标诊断 |
| 正例 ASan/UBSan | 六个程序 × 两套编译器，共 12 项 CLEAN_OBSERVED | 本次执行未报告相应工具能够发现的错误，不是完整生命周期证明 |
| 受控 ASan 反例 | 一个程序 × 两套编译器，共 2 项 DETECTED_AS_EXPECTED | 重新分配后读取旧元素指针被报为 `heap-use-after-free`，退出码均为 86 |

四次 sanitizer 能力探测均可用，不计入正文实验数量；本轮 SKIP 为 0。源码总计九个文件、八个有 `main` 的程序，不把不同配置下的重复运行称为更多独立实验。

观察结果与正文节选一致：同址重建案例经历 `live=0→1→0→1→0`；非委托外层构造失败只清理已完成构造的成员；经函数参数转发的临时对象没有获得第二次延寿；旧 span 保留原长度；删除后的合法下标可以指向另一条逻辑记录。生命周期结论仍依据正文引用的 C++23 规则，输出只是对应程序的执行证据。

没有执行析构与重建间隔中的非法成员访问，也没有执行转发引用的悬挂读取；这两类限制不能靠 sanitizer 无报告证明。没有覆盖继承/联合体复用、分配失败、全部构造形式、自定义 allocator 或通用失效矩阵。性能、并发动态检测、Linux/Windows、Zig/Rust 与 PDF 均未验证，本轮也没有重跑 v1 技术实验。

## 重跑与文档检查

在仓库根目录运行；输出路径必须是尚不存在的新文件。

```sh
python3 c++/rework/verify_g1.py \
  --compiler /usr/bin/clang++ \
  --compiler /opt/homebrew/opt/llvm/bin/clang++ \
  --output /tmp/g1-rework-results-new.json
```

命令会报告临时源文件与可执行文件的位置；这些路径是本次本机工件，不是永久交付地址。全部实验均可再次从正文提取。

文档结构与本地链接另用 `python3 c++/learning/check_docs.py` 检查；它不验证外部网站全部内容，也不验证 C++ 技术结论。新稿另外检查标题层级、围栏闭合、代码提取完整性与结果摘要绑定。两类检查与前面的执行证据分开，不汇总成“全系列正确”。

2026-10-01 实际检查结果：上述检查器解析 46 份 Markdown，检查 847 处本地链接，错误为 0；保留旧章节的 16 项代码／图示分页风险，不将其描述为本轮 PDF 验收。临时只读核对另外检查 `rework/` 六份 Markdown 的单一 H1、H1–H3 连续层级、显式锚点唯一性、围栏闭合及无 HTML 折叠依赖，均符合要求；两篇 G1、九份提取源码、执行器及复用辅助文件与结果中的摘要一致。

以本轮起点 `d45f9a7020c2888dda15445e63b64478d5c09ec4` 为准逐字节比较，13 篇 v1 G 章节、10 篇 FM 与两份仓库正式发布 PDF 共 25 个文件未变。既有文件的差异只涉及两份导航、G0 正文和 G0 说明；新增内容只在 `c++/rework/`。没有修改出版系统或其他历史记录，没有重建 PDF。
