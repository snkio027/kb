## 全书的组织方向

暂以五个部分组织知识，旧 G 编号用于追踪来源，不作为必须保留的最终章节边界。需要拆分的专题按问题和先修关系拆，而不是让一个章节承载所有相关名词。

| 部分 | 建议章节组织 | 如何增加实质深度 |
| --- | --- | --- |
| 程序与对象 | G0 工具链；G1 分为生命周期、借用失效、表示与类型化访问三个单元 | 从真实工件和具体执行路径建立模型，区分语言规定与实现观察 |
| 资源与值 | G2 分为资源清理、借用与交接两个单元；G3 复制、移动、赋值与返回；G4 容器、迭代器、算法与视图 | 沿一个资源类型和一个数据批次持续演进，解释失败路径、失效规则和不同实现的代价 |
| 抽象与机器成本 | G5 类型推导、约束与实例化；G6 分为布局与访问、分配策略与测量 | 从调用表达式推导具体类型；从访问工作量解释测量，而不是把泛型等同模板技巧、把性能等同耗时表 |
| 并发与交付 | G7 分为共享状态协议、原子操作与内存模型；G8 二进制接口；G9 构建和部署 | 先把互斥、等待、退出讲完整，再进入内存序；跟踪一份库从编译到外部使用，不提前用框架掩盖步骤 |
| 系统综合 | G10 运行时案例；G11 时间与物理系统；G12 跨语言模型对照 | 用前面已经解释的机制解决组合问题，保留取舍和失败历史，不重讲整本书或变成框架名录 |

这是重编路线，不是已经完成的新目录。G8 与 G9 的必要概念会在 G0 初次出现，后面负责展开 ABI 兼容、动态加载和工程交付，不重复一轮术语定义。Zig 与 Rust 用于检验模型是否可迁移，不在每节末尾强行添加对照；Zig Build 也不替代直接观察编译、链接命令。

## 每个重要主题需要讲到什么程度

一段讲解应让读者沿着具体状态或输入推导结论。例如“vector 扩容可能使指针失效”，不能在解释到这里就结束：应展示旧存储、元素迁移、新存储、旧存储释放之间的关系，区分只追加但未扩容的情况，并说明为什么不能通过某次地址没变判断接口合同。更深入的内容来自条件与因果，不来自再列十种容器。

关键实现不再长期藏在 `acquire()`、`build_state()`、`do_work()` 等占位函数后面。第一次建立模型可以省略细节，随后必须补齐真正影响结论的部分。反例先说明改了什么，再解释为何失败；不把偶发崩溃、特定性能数字或一次工具输出当作语言证明。

中文以完整论述为主。术语首次出现给出必要英文，之后统一使用中文；标识符保留原样。保留决定结论的限制，删除反复出现却不增加理解的“本质”“核心”“不是……而是……”口号。连续的短句、流程块和清单应转成有因果关系的段落，不只是换一种排版。

G0 精读反馈进一步确定了写作尺度：一个主问题贯穿章节，尽量沿同一个对象或程序改变条件；先用直观解释建立理解，再稳定专业术语。语言规则、实现机制和本机观察分层，关键机制由真实工件或状态变化解释，章节最后再压缩成回查模型和迁移题。后续继承这些方法，不要求相同节数、篇幅或实验数量。

章节结尾保留少量需要迁移推理的题目，并给出完整答案。不要再连续安排“统一模型、十五条原则、审查协议、常见误判、Final Gate”五种重复总结。进阶材料可以回查，但首次主线必须能够直接顺序读完。

## G0 这次具体改变了什么

旧 G0 的三个文件实验是良好入口，新稿继续使用小型双翻译单元程序，但沿同一个程序逐步回答：声明怎样支持编译、头文件到底带来了什么、符号和重定位各记录什么、改错签名为什么在不同阶段失败、头文件定义为什么可能重复、优化怎样改变可观察工件、静态归档怎样参与链接。

原先 G0 的结构体布局、ARM64 寄存器回查和跨语言句柄接口暂不挤在这一条主线上。它们仍保留在 v1 的 G0，并分别由后续对象模型、机器成本和 ABI 单元承接；不是以删除细节换取简短。G0 对加载器只建立边界，完整动态库故障留给 G8/G9。

G0 的 [验证记录](g00-verification.md)保留 `d45f9a7` 的源代码和执行结果身份；后续校准单独记录，没有追写旧摘要或假称重新运行。没有把 v1 的旧测试“全部通过”当作新稿通过，也不声称已经验证 Linux、Windows、Zig 或 Rust。自动结果不能回答文章是否真正易懂，这一项仍由实际精读反馈判断。

## G1 如何承接 G0

第一单元沿一个 `Reading` 对象区分存储、构造、析构和重建，再用成员构造失败、引用延寿解释生命区间的边界。透明替换按具体前提讲解，不把“地址仍在”或“析构过”当作通用结论。

第二单元改为同一类任务中的整数读数批次，依次改变范围长度、容量和删除位置，区分对象生命、借用失效与逻辑记录身份。它建立 G2 资源责任与 G4 容器规则所需的基础，不提前做容器选型大全。旧 G1 的完整值类别讲解转入后续 G3 主线；跨语言对照留作有明确比较对象时再写，不靠删去旧源稿来隐藏迁移范围。

三单元的普通运行、只读访问编译负例、ASan/UBSan 观察和受控失效访问分别登记在 [G1 验证说明](g01-verification.md)。类型化访问的反例只作语言规则分析，不假定工具必然诊断。正文不反复插入状态标签，工具结果也不代替实际阅读接受。

精读后的校准只补四处边界：借用是本书的工程分析术语，`const_view` 的 const 限制 span 对象，局部作用域不会释放运行时借用，以及存储持续期不同于对象生命周期。原有案例主线、实验判据及迁移题保留。

经确认，类型化访问与对象表示由短第三单元主讲，不延至 G6。它沿读数的字节视图、快照及独立结果，区分 `memcpy`、`bit_cast`、`reinterpret_cast` 的前提；这项安排补足访问正确性的基础，不把 G1 扩成二进制格式或对象模型词典。G6 后续只需承接布局与访问成本。值类别继续归 G3，联合体复用、完整 allocator 规则等不加入当前 G1。

`d071bf4` 的接受登记覆盖 G1 的中文论述、三单元组织和证据整合。冻结前仅将“相似类型”精确到对象的动态类型，并补明 strict aliasing 术语与编译器选项的可移植性边界，不再增加内容或实验。冻结正文摘要与历史执行证据的关系见 G1 验证说明末节；该收口没有重跑 C++ 或 sanitizer，也不构成 PDF 验收。

## G2 如何承接 G1

G2 从“对象和访问已经合法以后，谁负责让资源正确结束”出发。第一单元用真实临时文件建立最小 owner，解释获取后的未受管区间、提前返回、成员构造失败、移动赋值及显式关闭；第二单元用同一个 Batch 类型解释同步借用、消费型接口、共享生命、延迟任务与回调环。主线不按智能指针类型清单排列，也不把释放责任和业务成功混在一起。

[G2 验证说明](g02-verification.md)独立记录新正文与十二份提取文件。正常运行、已删除复制的编译诊断、ASan/UBSan 观察、错误变体拒绝分别报告；临时文件实际读写与人工返回值注入也分开，不把注入关闭失败称为真实磁盘故障。G0/G1 的正文、执行器及证据保持原字节。

旧 G2 中的事务更新细化、完整特殊成员规则留给 G3 与 FM 回查；线程停机和池租约只在新稿说明责任边界，完整同步实现归 G7/G10；机器人架构及跨语言对照留到相关应用单元。旧稿仍可定位，不通过删掉旧内容来掩盖迁移范围。本批不进入 G3，也不构建 PDF。

## 参考的采用边界

2026-10-01 提供的参考用于确定案例推进方法，不直接转抄其中的技术简写和版本判断。例如 `std::move` 本身不执行资源转移，容器容量不保证按某一固定数列增长，符号数量不等于源码中的模板特化数，并发问题也不能全部归结为内存序。后续正文应把这些条件讲清楚，而不是沿用更响亮的表述。

本轮不创建新课程平台、自动学习计划或通用实验框架，不动 FM，不重建 PDF。G0/G1 的实际阅读反馈已经支持推进 G2；当前仍逐章检验解释质量，不把前章获认可写成全系列已完成。
