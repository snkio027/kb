## 需要解释的观察，不是固定机器输出判据

以下结果在两套编译器的本轮输出中均被观察到，并与正文节选核对。执行脚本保留输出，但不把某个地址或固定指令序列设成跨版本通过条件。

- `main.o` 未定义的 `__Z3addii` 与 `calc.o` 的定义对应；解码后为 `add(int, int)`。
- `main.o` 的调用处有 `ARM64_RELOC_BRANCH26` 记录。链接后，该处的分支编码和目标改变，指向 `add`。
- 分离编译的 `main-O2.s` 仍调用 `add`；单翻译单元的 `single-O2.s` 中，`main` 只返回 0，但目标文件仍保留外部 `add` 定义。
- 归档列表有两个成员；链接映射只选入 `libcalc.a(calc.o)`。最终符号没有 `unused_value()`。
- 移走原归档不影响运行，但 `otool -L` 仍显示 libc++ 与 libSystem 依赖。
- 本机 `-MMD` 输出除两个用户文件外还包含 SDK 设置文件。因此它不能被解释为“恰好只列两份文件”，更不能替代完整构建输入清单。

这些是目标文件、指令和依赖观察，不是性能测量。没有执行 benchmark、并发动态检测、Linux/Windows 验证、Zig/Rust 实验或 PDF 构建；也没有重跑旧 G 系列实验。语言与 ABI 规则的解释依据正文所列资料，不以两次本地执行代替规范。

## 如何重跑

在仓库根目录运行下列命令；两个编译器和观察工具的路径针对本机。输出路径必须尚不存在，脚本不会覆盖旧记录。

```sh
python3 c++/rework/verify_g0.py \
  --compiler /usr/bin/clang++ \
  --compiler /opt/homebrew/opt/llvm/bin/clang++ \
  --output /tmp/g0-rework-results-new.json
```

脚本会报告临时工件目录，可以在那里查看汇编、链接映射和依赖文件。JSON 中的临时路径只用于解释本次命令，机器清理临时目录后不保证仍存在；可以从正文再次生成。
