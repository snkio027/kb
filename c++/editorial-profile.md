# Modern C++ 工程手册 · Editorial Profile

Version: 1.1 · 2026-10-03 · Content v2 编辑基线

本手册面向学习能力强、有工程经验、希望深入理解 Modern C++ 的高级工程师，不以熟悉所有 C++ 细则为先决条件。解释陌生概念，但不省略建立正确模型所需的理论；服务于长期学习与工程回查，不是按天数推进的课程。Markdown 是内容事实源，PDF 是有版本的阅读制品。本文件是 G0～G12 的单一编辑规则入口，章节不另设互相竞争的格式规范。应用状态见 [总导航](README.md)；制定规则不等于未编辑章节已经符合规则。

v1.1 明确理论深度、英文术语保留和规则／证据分层，当前用于 `rework/` 的 G0～G7 修订。v1.0 与已出版正文的历史身份由 Git 保留；本次不追改 v1 源稿、既有执行证据或已发布 PDF。

## 1. 阅读层与技术深度

主阅读层按问题、语义模型、机制、工程后果、边界与验证展开；回查层容纳细则、术语、审查清单和跨语言对照。两层都使用普通章节，不把重要规则或答案藏在 HTML 折叠块中。

专业化不等于缩成速查笔记。保留推导所需的假设、反例与限制；合并重复口号和断裂短句，不删掉改变结论的条件。跨语言对照放在 C++ 模型之后，不以未经验证的 Zig/Rust 片段替代 C++ 证据。

核心概念必须有可定位的理论说明，至少交代定义（definition）、关系（relation）、推导规则（rule）与适用边界（boundary）。案例负责给模型一个具体对象，理论负责解释其他输入；两者不能互相替代。先读正文应能解释“为什么”，离开案例也应能判断改变类型、状态、调用方式或线程关系后的结果。

技术深度用推理跨度衡量，不用术语密度、代码长度或实验数量衡量。应说明哪个前提支撑哪个结论、删除该前提会在哪里失效；涉及成本时给出变量、单位与模型假设，涉及并发时给出状态、不变量、同步边与进展条件。必要的理论放在相关章节，不集中塞到篇末，也不机械要求每节出现同一组标签。

语言／库合同、实现机制、工程策略与执行观察分别陈述。例如：overload resolution 是语言规则；某次生成了什么符号是工件观察；选择按值传参是设计决策；某内核更快是特定测量结果。标准依据支持规则，实验检验有限命题，二者都不能单独替代整个组件的正确性论证。

## 2. 标题与定位

- 每篇一个书名式 H1：`G编号 中文主题`；英文主题可作普通副标题。
- H2 是编号的主题章（章首“阅读入口”不编号），H3 是子主题。正文最多 H3，不用加深标题层级代替段落组织。细项使用带说明的普通段落或列表。
- 标题描述内容，不使用单独的数字、重复的“错误”或写作过程提示。旧定位锚点可以保留，但不恢复旧 Part 式视觉结构。
- 章首给出主阅读路线与回查入口。Final Gate 的问题与参考答案是两个可直接定位的普通章节，不设置分数门槛。

## 3. 术语与论述

中文承担解释与推导，英文承担稳定的专业定位。首次建立概念时给出中英文对应，此后允许直接使用常见英文术语；不要求“首次英文、之后全部中文”。caller／callee、owner／borrower、lifetime、value category、deduction／substitution／instantiation、working set、latency／throughput、happens-before 等，在能提高辨认度的位置保持英文。语法标识符不翻译，缩写首次展开。

不为了保留英文而逐句堆放双语同义词。正文使用自然中文句法，关键概念、理论小节和必要对照表保留稳定词形；同一对象不要在“调用者／调用方／主调方”等名字之间无理由切换。caller 与 callee 是相对于某次调用的角色，不是固定模块名；owner 与 borrower 是责任／访问角色，不直接等同于某种指针类型。术语的定义仍由主讲章节负责，导航表不成为第二份语言规则。

段落以“结论＋机制＋适用边界”为基本单位。重要主题至少能回答：为什么需要它，规则如何成立，最小例子说明什么，工程上何时使用，哪种输入使结论失效，怎样观察。无需把每一段强行套成七个小标题。

避免连续的“不是 X／而是 Y”、全段加粗和一句一段的演讲式节奏。短结论可以加粗；普通推导使用完整句子。引用块仅用于确有需要的注意、边界、危险提示，不用作普通正文的装饰。

## 4. 代码、实验与证据身份

每个 C++ 代码块前有可见身份，机器注释不能代替它：

| 身份 | 阅读合同 |
| --- | --- |
| 完整实验 | 标明实验 ID、文件名、编译模式及运行入口；多文件按同一实验组合编译 |
| 机制片段 | 局部说明，不承诺独立编译；依赖上下文与前提写在邻近正文 |
| 反例 | 指明编译失败、未定义行为、运行失败或逻辑错误；禁止作为生产实现复制 |

仅展示类型名或表达式的代码块仍属于机制片段。Shell 块标明用途；输出和关系图使用 `text`，不能把预期输出冒充实际记录。需要省略的片段明确使用占位符，不与可执行实验混放。

实验模块包含：命题、源文件、运行方式、预期观察、解释及未覆盖边界。负例必须区分预期诊断、超时、崩溃与环境不支持。性能实验的数值是观察，不以固定耗时或某个实现必胜作为通过条件。并发实验先给不变量、同步边和生命周期论证，再给动态检测；没有检测到错误不等于协议已证明正确。

四类证据分开报告：结构/链接、编译/负例诊断、性能观察、并发动态检测。记录平台、编译器、标准库、选项、源码摘要、命令、结果及 SKIP 原因。历史记录不改写成新版本的实测；本地执行不称作 CI。

## 5. 表格、图与提示

表格用于字段可对齐的比较，原则上不超过四列；长条件改为带身份的记录或列表，不靠缩小字体。ASCII 仅用于关系、状态、布局或顺序，单个术语和口号使用正文。图必须有邻近解释，不能新增原文没有的边关系。

提示写为普通 Markdown 引用，例如“注意：”“边界：”“危险：”。不引入专属 renderer 的 CSS、硬编码页面尺寸、空行撑页或私有分页指令。正文不以水平分隔线划分每一个短主题。

## 6. Final Gate 与引用

问题检验能否解释条件与因果，而不是默写术语。答案说明推理链、关键前提和常见误判，并能回到相应主题；不能只写“见上文”。原有问题可按主题分组，不以重排为由删除难题。

语言规则优先引用固定版本标准草案条款；工具行为引用官方文档并记录实际版本。外部链接检查与本地链接检查分开，读取来源不等于验证其中每项实现。明确区分标准保证、常见实现、当前实测和工程建议。

## 7. 出版源稿约束

未来 renderer 应使标题与首个正文块保持、表头在跨页时重复、长记录保留所属对象、代码续页保留实验/文件身份，并避免截断和不可读缩放。ASCII 图不得静默换行改变关系；过宽内容应重新编排并核对语义。长实验按文件或机制阶段组织，不为了强制同页破坏可运行源码。

本批只检查源稿风险：H4 及更深标题、重要折叠块、宽表、长行/长代码、孤立标题、过密分隔线。长代码和图形进入风险清单，不自动当作已发生的 PDF 缺陷，也不能把源码检查称作分页验收。未来必须在实际制品上验证目录、书签、断页、裁切与可读性。
