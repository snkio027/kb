## 3. 阅读产品与内容覆盖

### 3.1 独立完整阅读版

拟支持 00–05 六个独立视图，各自保留完整正文、文档 ID、版本、状态、章节/Requirement 编号和适用边界。共用设计系统，不强制使用同一套厚重前置页。

| 篇章 | 主要任务 | 阅读节奏与入口 |
| --- | --- | --- |
| 00 文档体系 | 确认权威、选择路径 | 紧凑导航；少前置页，不牺牲完整正文 |
| 01 方法论 | 连续阅读与理解推导 | Narrative，清晰论证与克制强调 |
| 02 工程参考 | 按 Stage/Gate 执行评审 | Reference，任务/输入/产出与模板定位 |
| 03 治理 | 查义务、权限、例外及符合性 | Reference，条款定位、判定顺序和范围 |
| 04 工程保证 | 查 Claim、Evidence 与论证 | Reference，类型化状态、字段和反例 |
| 05 生产运行 | 发布、恢复、事故与运行评审 | Reference，操作前提、恢复条件与清单 |

### 3.2 合订工作版

拟提供《系统设计与工程保证工作手册》作为六篇的统一阅读视图，不新增规范身份或权威。它从同一冻结源集合重新编排，不以拼接六个成品 PDF 为主实现。

结构为：统一封面与制品说明 → 一页任务导航 → 总目录 → 六篇完整正文 → 跨文档条款索引 → 术语/状态索引。只有生成的重复封面和通用导航可以合并；正文中的重复段落、属性表或适用条件仍须保留，除非以后有单独内容修订批准。

合订版使用一棵书签树和连续物理页码；逻辑定位保留 `ESD-GOV-001 · §10.2`，不得重编号成失去源关系的“第 83 节”。各篇入口显示自身 ID、版本、状态和角色；合订制品身份不代替六篇各自身份。组合清单逐篇列出精确版本，不因套系名称相同推定版本一致。

### 3.3 延后视图与非目标

任务速查版只能是带来源的受控摘录或导航，需保留要求的前提、范围、例外、否定和引用依赖；无法证明摘录覆盖完整时只给导航，不作为独立要求。Worksheet 仅用于明确的打印填写需求，不能把大面积空白表单混入默认屏幕阅读版。

首轮不开发大量速查册、交互表单、网站、数据库、插件系统或多个 PDF 引擎。案例、模板及试点材料将来可以独立列入出版清单，但保留非规范性角色和证据范围，不自动混入六篇正文。

## 4. 身份与导航合同

| 身份 | 内容 | 不允许混用 |
| --- | --- | --- |
| 内容身份 | Document ID、正文版本、原状态、源仓库/快照及字节摘要 | 不能因公开一个 PDF 就将 DRAFT 改成 BASELINE |
| 出版身份 | 视图、编排/组件/布局配置版本及锁定依赖 | 仅修分页不应自动升级 ESD 内容版本 |
| 构建身份 | 有效输入、配置、工具与字体身份及本次执行记录 | 同一内容版本不意味着两次输出字节相同 |
| 交付状态 | preview、candidate 或已批准公开的制品 | 不能替代内容批准或业务 Gate 决策 |

结构导航由文档 → 章节 → 关键条款构成。视觉目录保持可扫描，书签可更细且默认折叠。任务导航至少覆盖新系统设计、例外/符合性、生产发布、提交未知恢复和事故后修订；它是入口推荐，不改变主题权威。

引用目标使用“文档 ID＋稳定对象 ID＋明确源版本/快照”。对象包括章节、Requirement、图表及模板；内部锚点加文档命名空间，不能靠标题文本或页码唯一性。在不改六篇正文的阶段，可先设计外置锚点登记，绑定精确源块与摘要；漂移、重复或歧义时不得模糊匹配到看似相近的条款。

显示定位同时保留源文档 ID、条款编号及目标标题；合订视图可增加当前 PDF 页码。合订内已有目标优先内部跳转；独立视图或未收入合订的目标提供固定版本源链接及纸面可识别的定位，跨 PDF 跳转只能是增强路径。

缺失目标、重复锚点、错绑版本必须形成诊断；预览可带醒目的未解决标记，但候选验收不得把这些错误当成功。不得把未在本制品中的目标伪装为本地页码。

## 5. 内容保真与转换合同

### 5.1 保真覆盖

正文是权威源，编排不重写、概括或“优化”业务措辞。每个受转换块有来源位置、稳定身份、原始内容/摘要、输出对象及转换类型。完整视图须解释所有源块的去向、次数和顺序；新增目录、索引、页眉和装饰也要标为生成内容，不能冒充源文规则。

允许的变换须有明确映射：生成封面去重、目录/索引生成、章节编号的等值显示、表格转记录、分页续标及纯视觉换行。不得靠全局忽略空白、标点、标题或差异来宣布保真；代码空白、负号、数字、单位、否定词和范围条件尤其不能被通用归一化抹去。

表格转记录时，用表 ID、行/记录 ID、列/字段 ID 逐格对应；字段名、值、注释和所属记录完整保留。比较任务需要横向关系时仍用矩阵，不能仅为排版方便改变阅读关系。图形改绘必须映射源标签及边关系，不能为美观新增因果、权威或依赖。

### 5.2 不止比较数量

检查应贯通“源块 → 编排结构 → 排版输入 → PDF 中可读内容”，而不是在 AST 相同后就终止。标题/表格/代码数量仍有价值，但不足以发现否定词丢失、表格串行、条件与要求分离或图形关系错误。

拟采用文本/字段映射、输出文本提取、结构定位和视觉复核互补验证。提取器遇到字形、数学或复杂表格无法可靠比对时，记录无法判定的块并进行有范围的人工核验；工具错误或覆盖缺口不得默认为保真通过。字符一致也不证明条件在视觉和阅读顺序上仍正确关联，仍需关联与阅读任务检查。

### 5.3 显式语义，不猜测义务

内容角色表达“定义、警告、例子、Gate、代码、文本图”等语义，布局只表达宽度、续页和呈现方式。未来经授权可添加少量语义标记或显式外置映射；本轮不修改六篇正文。未标记的旧内容默认中性样式，不用关键词猜规范等级。

状态必须带所属层次，不能把下列值视作同一种“绿色成功”：

| 层次 | 示例值 | 呈现要求 |
| --- | --- | --- |
| 验证执行 | PASS | 显示执行层次，不推导 Claim 或发布资格 |
| 证据结论 | SUPPORTS | 保留证据作用范围 |
| Claim 状态 | SUPPORTED | 不被 Exception 授权改写 |
| 对象符合性 | CONFORMANT | 不自动推导特定 Gate 放行 |
| Gate 裁决 | GO | 保留对象、动作、范围和授权来源 |

状态定义仍来自 GOV/ASSURANCE，不在样式宏中建立新状态机。混合 MUST/SHOULD 的条款不得因标题含“必须”而整体染成强制义务；模板也不得为未验证的案例补上 PASS 或 BASELINE。

## 6. 版式、表格与分页合同

### 6.1 统一骨架与三种节奏

继续采用 A4、单面、单栏、数字阅读优先兼顾普通打印，软垂直节奏和 ragged bottom。章节首页继续承载正文，不强制奇数页开章，不因追求填满页面拉伸段距或整体缩放。

Narrative 用于连续论证，段间距克制，可保留首行缩进；Reference 用于条款查询，强化 ID、条件和引用，不堆叠彩色框；Worksheet 是单独的打印视图，延后制作。中文正文、标题和代码分别使用清晰的字体角色；字体文件定位、版本与摘要不写死在视觉主题中。

| 参数 | 后续试件的起点，不是本次冻结值 |
| --- | --- |
| 边距 | 左右约 22 mm，上约 20 mm、下约 24 mm |
| 正文 / 基线间距 | 10.5–11 pt / 约 16–17 pt |
| 表格与记录字段 | 9–10 pt；不可因内容过宽持续缩小 |
| 代码 | 约 9 pt，禁用连字，保留符号和可复制内容 |
| 一级标题 | 22–26 pt，避免标题区占据半页 |
| 色彩 | 深色正文、低饱和强调、少量浅底；语义不能只靠颜色 |

这些候选尺寸与旧设计存在取值差异，须经真实试件比较后决定，不在本轮更换字体或参数。工具版本与 CTeX/Tagged PDF 兼容性留待实施时核对官方资料；本轮不继承附件中的“当前最新版”结论，也不声明 PDF/UA 合规。

### 6.2 组件跨页约束

| 组件 | 拟定合同 | 不可接受处理 |
| --- | --- | --- |
| 二级 / 三级标题 | 二级后保留约四行或有意义首块；三级后约两行；按真实组件调整 | 孤立标题，或为机械行数制造巨大空洞 |
| 短原则 / 警告 | 尽量整体保持；过长时转可分页组件 | 任意缩小字号或使用超高不可拆盒子 |
| 长定义 / 论证框 | 可分页，轻量续标与首尾边框表达连续性 | 条件被孤立成另一条要求 |
| 普通代码 | 可跨页；续页保留语言、块标题与身份；视觉折行不写入额外字符 | 丢失缩进、代码连字改变辨识、复制混入续页标签 |
| ASCII 流程 | 保持空格，不自动折行；过宽时独立评审或保真改绘 | 静默换行或缩放到不可读 |
| 多页矩阵表 | 重复表头，保留行列关联；不让字段身份与值脱离 | 仅凭列数自动横置，跨页丢掉适用条件 |
| 超长单记录 | 转可分页的记录布局，续页重复记录身份 | 拆成无法确定所属对象的零散字段 |
| Gate / 检查清单 | 标题和第一项条件保持；长列表可自然续页 | 为整块保持而制造大空白，或混淆条件和授权 |
| 图表 | 尽量靠近首次引用；超页调整图形布局且保留源关系 | 整体缩成小字或发明正文没有的业务关系 |

需要比较短值时用矩阵；理解长字段对象时用记录。横置仅作必要例外并登记，不能以减少留白为由强行拉入下一整块。空白率只是人工复核信号，封面、正文尾页和打印工作表应采用不同判据。

可用模板及代码始终链接到固定版本原始文件；PDF 不能是复杂代码唯一复制来源。默认完整阅读版仍须保留源模板内容，另提供打印填写视图时不能静默删去默认版正文。

## 7. 编排系统的四个职责边界

```text
固定有效源快照 → 出版清单 → Pandoc AST → 身份/引用/角色校验
  → 视图编排与源块映射 → LaTeX 组件 → 候选制品
  → 保真/结构/视觉/阅读检查 → 单独批准 → 发布已检查字节
```

| 层次 | 职责 | 禁止承担 |
| --- | --- | --- |
| 出版清单 | 选择文档、源路径、阅读角色、视图及依赖；读取并验证正文身份 | 复制正文版本/状态定义成为第二个事实源 |
| 内容编排 | 完整视图顺序、生成前置页去重、命名空间锚点、目录索引、显式摘录及转换映射 | 自动总结规范、丢掉条件、把例子提升为要求 |
| 版式组件 | 网格、字体角色、标题、记录布局、代码、图形和续页 | 业务状态机、符合性或批准逻辑 |
| 构建与发布 | 固定输入、工具链、检查、缓存、制品身份、批准范围和发布动作 | 用构建成功代替内容基线批准或 ESD Gate |

拟在现有 `design/` 中增量增加清单、布局策略、锚点/转换映射和检查入口，复用已有 Lua/LaTeX 组件。是否采用 `catalog.yaml`、`layouts/` 或 `pub.py` 等名字由实现合同确认；本轮不创建这些文件，也不预建空模块。兼容旧入口时须明确转为安全预览或拒绝旧发布行为，不能保留隐式 dist 写入通道。

## 8. 预览、候选与发布合同

以下 `pub preview / candidate / publish` 仅是拟定命令模型，不是可执行指令。

| 操作 | 输入与检查 | 输出与禁止项 |
| --- | --- | --- |
| preview | 可接受草案和未提交改动，但绑定实际有效输入摘要并标明 dirty 状态 | 仅预览区，显式 PREVIEW 和原内容状态；成功、失败、取消均不改历史 dist |
| candidate | 明确的不可变源集合、出版配置、工具/字体及完整原始执行记录 | 仅候选区；保真、结构等未通过或未覆盖项保持可见，不自动公开 |
| publish | 匹配同一候选字节、检查记录及范围明确的制品公开批准 | 只发布已检查字节，禁止临时重编译；不覆盖历史版本，不改写内容状态 |

候选必须从隔离冻结的有效输入构建，不能只记一个 commit 却读取漂移工作树。内容、配置、锁文件和字体身份都参与构建身份；同源不同配置不得误复用缓存或检查记录。目录候选为 `build/preview/<build-id>/`、`build/candidate/<build-id>/` 和 `dist/<publication-id>/`，历史 dist 原位保留。它与计划中按 source-snapshot 组织路径的建议需在实施前统一；本轮不改变路径。

正式发布前后校验候选/目标摘要及完整性；缺失批准、范围错绑、摘要改变或目标同名不同字节时拒绝发布。途中失败不能留下可被误认为完整发布的半套文件或成功清单；重试先核对既有目标，不能覆盖重做。输出路径还需拒绝经符号链接或路径逃逸写入受保护目录。具体原子提交和恢复机制在发布实现批次明确，不在本轮声称已具备。

公开草案阅读件与批准规范为 BASELINE 是不同动作。草案冒充基线的发布必须拒绝；若以后允许公开标明 DRAFT 的阅读件，也必须单独批准对应制品及范围，且不提升内容状态。允许的交付类别矩阵是实施前待决项，不从本设计开放默认草案发布。

清单至少绑定：源 repository/commit/逐文件摘要、六篇身份与版本组成、视图/出版版本、配置/图表/模板/过滤器/锁文件摘要、实际工具及字体、内容源时间与实际构建时间、输出摘要、检查记录及批准对象。内容批准与最终制品批准分别引用，避免文件最终摘要写回自身或产生批准/清单摘要循环。

## 9. 拟验收：保真、结构、视觉与阅读

### 9.1 四类出版检查

| 检查 | 需要的证据 | 通过边界 |
| --- | --- | --- |
| 内容与编排 | 块映射、出现次数/顺序、Requirement/数字/条件比对、字段关联及负向样例 | 只覆盖声明的转换和输入；人工结论与自动结果分开 |
| PDF 结构 | 字体嵌入、缺字、元数据、目录/书签、锚点、页码标签、链接及搜索复制 | 不代表视觉正确、业务符合性或 PDF/UA 合规 |
| 视觉 | 全页基本异常检测＋章节首页、最长条款/代码、宽表/记录、全部横置、图表、续页和末页人工复核 | 不把留白一律判错；保留无法自动判定项 |
| 阅读任务 | 任务路径、实际操作次数、误读/返回记录及使用者反馈 | 不能用设计目标代替测量，也不以一次自演练证明普遍可用性 |

出版实现的退出码 0 不等于这四项均通过。任何检查器未执行、报错或结果不完整，分别记录，不能转换为 PASS。视觉回归待完整内容和试件稳定后建立，优先按源块/章节定位差异，不仅按页号机械比较。

### 9.2 阅读任务与试件覆盖

拟定任务：从入口找到 Exception 与 Claim 的关系及范围；从 OPS-REQ 索引定位条款；核对 CAN 未知提交的正文/图形/引用；找到固定版本模板源；辨识当前材料是规范、案例、试点还是草案。主要任务两到三次导航动作内完成仅作为待验证目标，实际结果应留记录。

后续短试件拟覆盖：方法论长段落、混合义务、有条件 Gate、十字段记录、多页代码、长英文标识、ASCII 流程、跨文档引用、说明性反例及试点证据摘要。每个片段绑定真实源快照及节选范围；试件明确是排版样本，不冒充完整规范或实现证据。本轮没有创建试件或测量阅读效果。

### 9.3 首批负向场景与预期 Oracle

| 场景 | 预期拒绝或诊断 | 归属 |
| --- | --- | --- |
| 预览成功、失败、中断，或经旧入口调用 | 历史 dist 字节不变；不得写入成功发布记录 | B1-A |
| 输出路径通过符号链接指向 dist | 拒绝越界写入，保留诊断 | B1-A |
| 草案套用固定“基线”文字或另一篇标题 | 身份检查拒绝候选；不篡改源状态来消除错误 | B1-B |
| 内容删掉“不得”但块数量不变 | 文本保真检查检出差异，不能仅凭计数通过 | B2/B4 |
| 记录布局交换两行字段值或漏掉例外 | 源单元格/记录映射失败，不接受视觉近似 | B2/B4 |
| 合订存在重复锚点、错绑版本或编号漂移 | 引用/身份检查失败，定位到具体源对象 | B3/B4 |
| ASCII 折行、代码复制混入续页标签 | 对应保真/复制检查不通过，不靠缩字掩盖 | B2/B4 |
| 未知检查结果显示绿色 PASS | 状态层次或结果记录校验失败 | B4 |
| 候选摘要改变、批准缺失/错绑、目标已存在且字节不同 | 拒绝发布，不重新构建或覆盖目标 | B5 |
| 发布复制途中失败 | 不暴露为完整发布；按明确恢复合同保留或清理暂存 | B5 |

这些是检查设计与预期结果，**未执行，不计为测试通过**。B2/B3 引入转换时就要随同实现其相关保真检查，不能等到 B4 才发现内容损坏。

## 10. 分批实施边界

下面是供后续独立授权的切片，不新增一套 ESD 审批体系，也不以 B 编号表示当前已经启动。

| 批次 | 范围与依赖 | 明确排除 | 拟退出条件 |
| --- | --- | --- | --- |
| B1-A：发布隔离 | 对应 WP-02 的输出/入口安全；审查 build、check、render、manifest 及兼容入口的写入边界 | 不改正文、字体、主题、组件或全篇编排；无需实现完整发布服务 | 成功/失败/取消均不改历史 dist，路径越界被拒绝；在发布实现尚未合格时关闭正式发布入口 |
| B1-B：最小身份渲染修正 | 单独的安全配套修改：从元数据读取标题/ID/版本/状态，删除模板强加的“基线”资格 | 不属于完整视觉重设计，不顺带替换字体或重做封面/分页 | 六篇身份 fixture 不套错标题，草案在可见页面和元数据中不升格；所需模板/过滤器范围须单独获批 |
| B2：真实内容试件与组件 | 依赖 B1-A/B1-B；固定少量真实片段，验证阅读骨架、矩阵/记录、代码和续页，同时建立相应保真检查 | 不接入全部正文，不先重画封面，不调整核心规范语义 | 样本身份、内容映射与视觉合同可核对；参数选择有比较依据 |
| B3：完整阅读视图 | 依赖合格组件及转换检查；逐步接入六篇独立版和合订版，目录/锚点/编号/索引 | 不自动加入速查册、Worksheet 或全部试点材料 | 完整正文去向可追溯，跨文档引用与页面定位正确，身份不漂移 |
| B4：完整验收与回归基线 | 汇总并补全全量保真、结构、视觉及阅读任务；此前批次已有必要局部检查 | 不把最终验收当作前序无检查的理由 | 负向样例、全部页面检查和阅读记录范围明确，剩余未知不隐藏 |
| B5：受控发布 | 独立实现/验收发布事务、恢复及批准绑定；依赖合格候选与实际授权 | 不重新构建候选，不覆盖旧版本，不把 DRAFT 升为 BASELINE | 发布确为已检查字节，清单/批准/来源一致，失败恢复和重试不制造假成功 |

“第一批仅改入口和路径”只能承诺 B1-A 的隔离结果，不能顺带承诺模板身份正确。因此 B1-B 的最小模板/元数据接线另列范围，须与 B1-A 一起完成后才制作新版试件；这不把 B2～B5 的完整重设计塞进 WP-02。若未来选择合并 A/B 为同一提交，也必须在启动合同中明确文件与验收范围，不能从本文推定授权。
