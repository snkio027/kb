# 项目试点

本目录保存真实项目中的试用记录，不新增规范要求，不代替项目批准、生产放行或完整符合性声明。采用的文档基线为 `kb@a67fb259d9a37bfcfc0c3b6b6418aeb06bd6aac2`，即六篇 Markdown 的 `2.0.0-draft.1`。

## R1 / R2 是什么

R 表示风险等级，不是项目编号或迭代阶段。定义及评审独立性以 [03 §4、§6](../../03-系统设计与工程保证治理及符合性规范-v1.0.0.md) 为准。

| 等级 | 适用对象 | 最低评审独立性 |
| --- | --- | --- |
| R1 · Bounded Production | 影响有限且可隔离、恢复成本中等，例如单团队辅助服务 | 至少一名非作者 Reviewer；Owner 接受运行责任 |
| R2 · Core Production | 影响核心业务、关键数据或跨团队依赖，例如数据平台或关键控制面 | 至少两个责任主体交叉评审设计、运行与证据；最终批准不由单一作者完成 |

试点意图是检验不同风险下的要求是否可用，不要求必须选择两个仓库。同一项目可以提供不同变更案例，但每个案例必须独立说明后果、范围和定级依据；涉及安全、凭据等高后果边界时还需评估 R3，不能为了完成 R1/R2 试点而降低等级。

## 下一轮如何完成试点

1. Atlas Owner 指定一个真实待评审变更，确认对象、提交、环境、影响范围及风险等级；映射具名责任人。复用 [02 §13 的评审模板](../../02-优秀系统设计-从约束不变量到证据-v1.1.0.md)，不再另造一套表单。
2. 由满足风险等级独立性要求的 Reviewer 对同一固定证据分别记录结论，再比较分歧；未经独立复评不能声称判定一致。
3. 记录材料准备、证据采集和评审的实际耗时，以及每次条款解释分歧。测试运行时长不能代表人工成本。
4. 依据真实反馈决定保留基线、窄范围修订或继续试用。涉及生产、Tier-0、恢复或凭据的操作另行授权；本目录不提供这些授权。

退出条件是：选定案例完成所需角色评审，分歧有处置记录，证据成本可衡量，剩余风险和下一步有责任人。仅有测试 `PASS` 不构成试点完成。
