## 发布是什么

发布是将**一个已接受、身份明确且摘要固定的候选字节集合**，按批准的版本、文件名与位置提供给读者，并附可验证的摘要和发布记录。Git 审核包可见、构建成功、用户接受候选、命令名为 publish 都不单独构成正式发布。

发布时消费已批准候选，不能临时重新编译；若需要更改封面、状态、元数据、正文、导航或排版，先形成新候选并完成适用检查，再单独批准其摘要。来源、执行输入和工具身份继续使用候选 manifest，不以当时最新 main 代替实际构建输入。

## 拟定发布载荷与读者校验

最小发布包应含最终 PDF、`SHA256SUMS`、发布记录以及来源／候选绑定 manifest。清单至少记录最终文件名、字节数、SHA-256、内容 commit、视觉 commit、候选 ID／提交、批准范围、阅读器实测范围、已知限制。发布记录可另行登记最终 Git commit/tag；不要把文件最终摘要写回文件自身。

本轮 [SHA256SUMS](SHA256SUMS) 只校验现有候选。仓库根目录的实际检查命令：

```sh
shasum -a 256 -c publication/reviews/release-qualification/SHA256SUMS
```

正式发布时应从最终获批候选生成以**实际下载文件名**为路径的清单。读者在同目录运行 `shasum -a 256 -c SHA256SUMS`，或在 Windows 使用 `Get-FileHash -Algorithm SHA256 <文件名>` 与可信发布记录比较。摘要匹配证明字节一致，不单独证明来源可信、代码正确或发布批准；下载后还须核对发布者提供的版本和绑定记录。本轮没有正式下载地址，也没有执行下载复验。

## 版本演进与已知限制

出版版本与章节内容版本分开。任何 PDF 字节变化均需新候选及新摘要；正式发布后不原位替换旧资产。纯出版修正可以拟用 1.0.1；正文修订或有意义的整书变更拟用 1.1，重大重组拟用 2.0，具体升级在下一次批准时确定。不因新版出版而改写旧实验或旧审核证据。

发布记录必须携带既有非阻塞限制：TOC／Gate 留白、个别 Gate 类别标签落页尾、长代码局部软折行和章节收尾节奏。不宣称它们已修复。出现内容丢失、代码截断、危险身份丢失、错误链接、表格语义损坏或严重不可读时停止发布；普通审美差异不触发再设计。
